# SoccerTrainingApp — complete delivery planning package

8 September 2026 • Planning only

Start with [soccer_agent_activity_plan.md](soccer_agent_activity_plan.md). It decomposes the requirement plan into 390 activities with goals, deliverables, dependencies and acceptance checks. [soccer_delivery_master_plan.md](soccer_delivery_master_plan.md) defines the product baseline and twelve phases.

## Contents

- **soccer_human_action_playbook.md:** fourteen detailed human action cards, role responsibilities and acceptance records.
- **soccer_agent_execution_playbook.md:** bounded assignments, repository/environment controls, implementation invariants and review handoffs.
- **soccer_delivery_backlog.md:** 165 detailed planning records, preserving SP-001–SP-150 and adding SP-151–SP-165 for the five immediate priorities.
- **soccer_agent_activity_plan.md**, **soccer_agent_activity_manifest.json**, **soccer_agent_activity_tasks.csv** and **activities/P00.md–P11.md:** 327 agent activities, 21 human actions and 42 acceptance rollups; first assignment sequence and copyable agent brief. The activity CSV is not a Linear import route.
- **soccer_feature_traceability.md:** thirty feature groups, all 33 specified screens, 27 security risk themes and 20 review actions linked to delivery and verification.
- **soccer_linear_setup_and_import.md:** the documented import path and the required second pass for projects, milestones, parents and dependencies.
- **soccer_linear_import.csv:** full 165-issue CSV. Alternatively, use **soccer_linear_smoke.csv** (three records) followed by **soccer_linear_remaining.csv** (162). Do not import both routes.
- **soccer_linear_manifest.json:** structured tasks, relationships, phase mapping and unresolved run-contract fields.
- **soccer_acceptance_evidence_register.json:** 613 planned acceptance criteria, including priority additions; original IDs are retained and actual evidence/approvals remain blank.
- **source_manifest.json** and **baseline/:** exact snapshots of the seven earlier specifications used, including the latest Light/Dark and logo-export design requirements.
- **activity_plan_validation.md:** checks on the current activity breakdown. **validation_report.md** retains the historical baseline checks.

The root delivery backlog is the current breakdown. The backlog inside baseline is the historical 74-issue snapshot retained for traceability. Existing product and security contracts are not discarded; the latest design section 9 supersedes older palette concepts.
