# SoccerTrainingApp — Human Action Playbook

Humans retain ownership of decisions, approvals, consent, specialist judgement, spending, customer contact and production release.

## Roles

| Role | Accountable work |
|---|---|
| Founder / product owner | Scope, budget, brand, packaging, business decisions |
| Delivery owner | Board, dependencies, acceptance records, assignees and blockers |
| Technical lead | Architecture, code review, implementation/security decisions |
| Qualified coach / content owner | Drill suitability, movement parameters and release approval |
| Animator / designer | Source assets, design system, accessibility and production files |
| Privacy / security reviewers | Data flows, recovery, security findings and release risks |
| Safeguarding owner | Sensitive reports, escalation and alternative reporting route |
| Operator / recovery custodian | Deployments, alerts, backups, restore and credentials |
| Research / club coordinator | Pilot recruitment, consent-aware research and findings |
| Billing / accounting adviser | Pricing, tax treatment, invoices, refunds and operating model |
| Release owner | Go/no-go, store publication and rollout control |

## H01 — Approve scope and assumptions

Confirm first market/language, ages 5–18, direct-family plus club routes, both recording modes, hierarchy, pilot representation and explicit v1 exclusions. Record unresolved assumptions instead of silently treating them as approved.

## H02 — Establish brand ownership and export treatment

Approve app name, editable logo masters, commercial rights, light/dark variants, logo-first export treatment, source audio/orientation behavior and share/export permissions.

## H03 — Commission and approve curriculum

Use an appropriately qualified youth coach, plus goalkeeper expertise where relevant. Review all released drill variants for movement, age/ability suitability, prerequisites, space, equipment, assistance, work/rest, cues, captions, animation accuracy and source rights. The starter set is 12 drills; it is not the permanent authoring limit.

## H04 — Validate UX across roles and themes

Review player, parent, coach, club and platform flows in Light/Dark. Include permission denial, no-camera path, quota states, interruptions, safeguarding, MFA/recovery, account transition and outdoor readability. Recheck implemented accessibility before pilot.

## H05 — Approve data, privacy, recovery and safeguarding

Review actor/resource/action access, processors/regions, retention, media grants, guardianship disputes, age-18 transition, lost-factor recovery, privileged recovery, safeguarding recipients and alternate escalation. Do not ask users to send passwords, TOTP codes or seed secrets.

## H06 — Set up board, repository and bounded agents

Choose organization-owned accounts, repository, environments, Linear mapping, reviewers, spend/time ceilings and allowed paths. Prove branch/review restrictions and one bounded agent run before wider delegation.

## H07 — Set device targets and accept feasibility

Define named iOS/Android devices and measurable tolerances. Review camera start/finalize, timers, long capture, interrupts, export, local persistence, MFA/player credentials, access denial, upload and sandbox billing evidence. Make a go/revise/stop decision with revised scope and estimate.

## H08 — Review implementation evidence

Review small bounded changes tied to exact commit/build/config/content version. Check both successful behavior and negative access cases. Reject stale or incomplete evidence. Parent/work-package closure requires all relevant child work plus original integration acceptance.

## H09 — Independently accept security and pilot operation

Arrange independent review and retest of blockers. Rehearse credential compromise, restore, deletion/revocation replay, backup operator access and safeguarding/support routing using synthetic data before involving real children.

## H10 — Run controlled family/club research

Recruit through authorized channels, obtain separate product/research/media permissions, include intended age/device/assistance segments, test no-camera and optional-sharing journeys, minimize identifying research notes and honor withdrawal.

## H11 — Approve subscriptions and economics

Validate family/club value, monthly/annual pricing, tax, seat minimum, staff inclusion, cloud quotas, retention, cancellation/refunds, store-vs-web ownership, supplier costs, support load, founder capacity and runway. Test products are not live prices.

## H12 — Prepare business and release ownership

Complete required entity/IP/contract/tax/privacy/support work with appropriate specialists. Ensure store declarations match the actual build and actual SDK/data behavior. Verify domain/email/account recovery ownership and staged release runbooks.

## H13 — Approve exact release

Confirm the signed artifact, configuration, content and evidence manifest; no unresolved blocker in advertised scope; named rollout audience; and live support ownership. Record submitted, approved and live states separately.

## H14 — Operate and decide future investment

Review incidents, reliability, spend, renewals, dependencies, access, restore, retention, content and adulthood transitions on a regular cycle. Promote wishlist items only with observed demand, scoped design, rights/security review, cost/capacity and explicit acceptance criteria.
